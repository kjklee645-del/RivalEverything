# PLAN.md 한국어 업데이트 계획: Unity 비전 유지 + 현재 웹 프로토타입 반영

## 요약
- 장기 목표는 계속 **Unity 기반 iOS/Android 모바일 판타지 RPG**로 유지한다.
- 현재 repo의 JS/Canvas 버전은 최종 엔진이 아니라, 핵심 루프를 검증하는 **Phase 0 웹 프로토타입**으로 명확히 정의한다.
- `PLAN.md`는 “이미 Unity 개발 중인 프로젝트”처럼 보이지 않도록, 현재 구현 상태와 향후 Unity 전환 계획을 분리해서 다시 작성한다.

## 현재 개발 버전
- 현재 빌드는 `index.html`, `styles.css`, `src/app.js`, `src/game-core.js`로 구성된 정적 웹 프로토타입이다.
- 구현된 핵심 루프는 다음과 같다:
  - 플레이어가 3개의 윤리 축을 선택한다.
  - 선택값을 바탕으로 플레이어 정체성과 반대 성향의 “대칭자”가 생성된다.
  - 작은 섬의 3개 딜레마를 해결한다.
  - 플레이어 선택에 따라 세계 지표가 변한다.
  - 각 마일스톤마다 대칭자가 다른 장소에 반대 선택의 흔적을 남긴다.
  - 모든 딜레마를 해결하면 대칭자의 흔적 하나를 통합해 엔딩을 본다.
- 현재 검증된 도메인 로직:
  - `IdentityProfile`: 플레이어/대칭자의 윤리 축 프로필 생성 및 반전.
  - `Dilemma`: 장소, 축, 선택지, 결과, 세계 변화량.
  - `RivalMove`: 대칭자가 남기는 반대 선택의 흔적.
  - `WorldResponse`: 온기, 균형, 숨결, 균열 지표와 세계 판정.
- `tests/core.test.js`는 프로필 반전, 딜레마 해결, 대칭자 흔적 생성, 통합 엔딩 텍스트를 검증한다.

## 장기 Unity 비전
- 최종 제품은 모바일 우선의 Unity RPG로 유지한다.
- Unity 버전은 현재 웹 프로토타입의 구조를 가져가되, 다음 요소를 확장한다:
  - 3D 판타지 월드
  - 캐릭터 생성 및 성장
  - 실시간 전투
  - 퀘스트 진행
  - 장비/스킬/레벨 시스템
  - 모바일 터치 UI
  - 오프라인 저장
- 기존 `PLAN.md`의 “전투 중심 RPG” 방향은 폐기하지 않고, 현재 프로토타입의 “윤리적 대칭자/세계 반응” 구조 위에 얹는 장기 확장 목표로 재정의한다.

## PLAN.md 주요 개편 내용
- “Current Development Snapshot / 현재 개발 스냅샷” 섹션을 추가한다.
  - 현재 구현된 웹 프로토타입의 범위와 한계를 명시한다.
  - 아직 Unity, 3D 전투, 저장 시스템, 장비 시스템은 구현되지 않았음을 분명히 한다.
- “Design Pillars / 디자인 핵심 기둥”을 현재 버전에 맞게 수정한다.
  - 정체성 선택
  - 대칭자 생성
  - 장소별 딜레마
  - 세계 지표 변화
  - 반대 흔적 통합
  - 이후 Unity RPG 시스템으로 확장
- “Technical Architecture / 기술 구조”를 현재와 미래로 나눈다.
  - 현재: HTML/CSS/JavaScript/Canvas 정적 프로토타입.
  - 미래: Unity 2022 LTS 또는 이후 LTS, 모바일 입력, 저장, 3D 렌더링, AI/전투 시스템.
- “Migration Bridge / Unity 전환 브리지”를 추가한다.
  - 현재 도메인 모델을 Unity의 ScriptableObject, C# 모델, 또는 JSON 데이터로 이식할 수 있게 설계한다.
  - 웹 프로토타입은 최종 코드베이스가 아니라 디자인 검증 자료로 취급한다.

## 단계별 로드맵
- Phase 0: 웹 프로토타입 검증
  - 현재 핵심 루프 구현 완료.
  - 남은 작업은 플레이테스트, 텍스트/밸런스 조정, UI 피드백 개선.
- Phase 1: 프로토타입 고도화
  - 선택 결과의 가시성 강화.
  - 대칭자 흔적의 의미를 더 명확히 전달.
  - Unity로 옮길 데이터 구조와 용어를 확정.
- Phase 2: Unity 버티컬 슬라이스
  - 현재 웹 프로토타입의 3개 축, 3개 딜레마, 대칭자 흔적, 통합 엔딩을 Unity에서 재현.
  - 전투와 오픈월드는 최소 수준으로만 붙여 핵심 루프가 살아있는지 확인.
- Phase 3: RPG 시스템 확장
  - 실시간 전투, 스킬, 장비, 레벨업, 퀘스트를 추가.
  - 대칭자가 단순 텍스트 흔적을 넘어, 전투/퀘스트/세계 상태에 직접 개입하도록 확장.
- Phase 4: 모바일 완성도 및 출시 준비
  - iOS/Android 최적화.
  - 저장/로드, 접근성, QA, 성능 측정.
  - 스토어 이미지, 아이콘, 소개 문구 등 출시 자료 준비.

## 테스트 및 검증 계획
- 문서 업데이트 후 `PLAN.md`를 읽어 현재 상태와 미래 목표가 혼동되지 않는지 확인한다.
- 코드 변경이 없더라도 `node tests/core.test.js`를 실행해 현재 프로토타입의 핵심 로직이 유지되는지 확인한다.
- 플레이테스트 기준:
  - 플레이어가 “내 선택”과 “대칭자의 반대 선택”을 구분할 수 있어야 한다.
  - 세 딜레마를 해결한 뒤 통합 엔딩의 의미가 이해되어야 한다.
  - Unity 버전으로 확장할 때 유지해야 할 핵심 재미가 무엇인지 드러나야 한다.

## 가정 및 기본값
- 사용자의 선택에 따라 Unity 모바일 RPG 비전은 유지한다.
- 현재 웹 버전은 버리는 산출물이 아니라, Unity 개발 전 핵심 시스템을 검증하는 설계 원형으로 사용한다.
- 이번 작업은 `PLAN.md` 문서 업데이트 계획이며, 코드 구현 변경은 포함하지 않는다.
- 향후 구현자는 이 계획을 바탕으로 먼저 문서를 정리하고, 그 다음 Unity 전환 또는 웹 프로토타입 고도화 작업을 선택할 수 있다.
