# MVP-SPEC-ko.md: Rival Everything 웹 MVP 구현 명세

## 1. 문서 목적

이 문서는 AI 에이전트와 1인 개발자가 바로 작업을 나눠 구현할 수 있도록 만든 MVP 구현 명세다.

기준 기획 문서는 `docs/PLAN-ko.md`다. 이 문서는 그중 3개월 MVP를 실제 작업 티켓, 파일 소유권, 데이터 구조, 화면 흐름, 테스트 기준으로 풀어낸다.

이 문서의 목표는 다음 질문에 답하는 것이다.

- 어떤 기능을 지금 만든다?
- 어떤 기능을 지금 만들지 않는다?
- 어떤 파일을 수정해야 하는가?
- 어떤 순서로 개발해야 하는가?
- 어떤 테스트가 통과하면 완료인가?
- 어떤 콘텐츠가 MVP에 포함되는가?

## 2. MVP 한 줄 정의

현재 웹 프로토타입을 확장해, 5~15분 안에 끝까지 플레이 가능한 작은 철학 RPG 버티컬 슬라이스를 만든다.

핵심 루프:

`정체성 선택 -> 딜레마 선택 -> 세계 변화 -> 대칭자의 반대 흔적 -> 통합/회고 엔딩`

MVP는 Unity 게임이 아니다. AI 생성 게임도 아니다. 먼저 수작업 콘텐츠와 규칙 기반 도메인 로직으로 핵심 재미를 검증한다.

## 3. 현재 repo 구조

현재 주요 파일은 다음과 같다.

| 파일 | 역할 |
| --- | --- |
| `index.html` | 정적 HTML 구조, 화면 패널, 오버레이, 버튼 |
| `styles.css` | 전체 레이아웃, 반응형 스타일, 모바일 UI |
| `src/game-core.js` | 도메인 데이터와 순수 게임 로직 |
| `src/app.js` | 브라우저 UI, 캔버스 렌더링, 입력, 화면 갱신 |
| `tests/core.test.js` | Node 기반 핵심 로직 테스트 |
| `docs/PLAN-ko.md` | 기준 기획 문서 |
| `docs/MVP-SPEC-ko.md` | 이 구현 명세 |

현재 코드 구조상 `src/game-core.js`를 먼저 안정화하고, 그 다음 `src/app.js`, `styles.css`, `index.html`, `tests/core.test.js`를 수정하는 순서가 좋다.

## 4. MVP 범위

### 포함한다

- 정체성 선택 3축
- 대칭자 자동 생성
- 딜레마 5개
- 장소 5개
- NPC 5명 이하
- 세계 지표 4개
- 대칭자 흔적 5개 이하
- 통합/회고 엔딩
- 최소 저장/재개
- 모바일 기준 UI 개선
- 핵심 로직 테스트 확장

### 포함하지 않는다

- Unity 전환
- 실시간 전투
- 장비와 인벤토리
- 스킬트리
- 대형 오픈월드
- 무한 AI 생성
- 서버
- 로그인
- 과금
- 복잡한 관계 시뮬레이션
- 직업 네트워크 전체

### 선택적으로만 고려한다

다음은 시간이 남을 때만 한다.

- 간단한 플레이 로그
- 엔딩 2종 이상
- 접근성 토글
- 콘텐츠 디버그 패널

## 5. MVP 성공 기준

MVP는 다음 조건을 만족하면 완료로 본다.

### 기능 기준

- 새 게임을 시작할 수 있다.
- 3개 윤리 축을 선택할 수 있다.
- 대칭자가 반대 성향으로 생성된다.
- 5개 딜레마를 모두 해결할 수 있다.
- 각 딜레마 이후 대칭자 흔적이 생성된다.
- 세계 지표가 플레이어 선택과 대칭자 흔적에 따라 변한다.
- 모든 딜레마를 해결하면 통합/회고 엔딩으로 이동한다.
- 플레이어는 대칭자의 흔적 중 하나를 선택해 엔딩 텍스트에 반영할 수 있다.
- 브라우저 새로고침 후에도 진행 상황을 재개할 수 있다.
- 새 게임으로 초기화할 수 있다.

### 품질 기준

- `node tests/core.test.js`가 통과한다.
- 모바일 폭 390px 기준에서 주요 텍스트가 버튼/패널 밖으로 넘치지 않는다.
- 한 세션의 기본 플레이 시간이 5~15분 안에 들어온다.
- 딜레마 한 개의 본문은 모바일에서 과하게 길지 않다.
- 대칭자가 단순 악역이 아니라 반대 가능성으로 읽힌다.

### 플레이테스트 기준

3~5명에게 플레이시킨 뒤 다음 질문에 답을 기록한다.

- 대칭자가 무엇인지 설명할 수 있는가?
- 기억나는 선택이나 결과가 있는가?
- 텍스트가 길거나 피곤했는가?
- 다른 정체성으로 다시 해보고 싶은가?
- UI에서 길을 잃은 순간이 있었는가?

## 6. 핵심 게임 루프 상세

### 1. 정체성 선택

플레이어는 시작 화면에서 3개의 축을 선택한다.

| 축 key | 왼쪽 | 오른쪽 |
| --- | --- | --- |
| `care` | 자비 | 효율 |
| `agency` | 자유 | 질서 |
| `bond` | 신뢰 | 통제 |

각 축은 선악 구도가 아니다. 두 선택 모두 세계를 살릴 수도, 상처 입힐 수도 있어야 한다.

### 2. 대칭자 생성

대칭자는 플레이어의 축 선택을 모두 반전한 프로필이다.

예시:

- 플레이어: 자비 / 질서 / 신뢰
- 대칭자: 효율 / 자유 / 통제

대칭자는 플레이어가 틀렸다고 말하기 위해 존재하지 않는다. 대칭자는 플레이어가 선택하지 않은 가치가 세계에서 어떤 결과를 만드는지 보여준다.

### 3. 딜레마 해결

플레이어는 지도에서 장소를 방문하고 딜레마를 해결한다.

각 딜레마는 다음을 포함한다.

- 장소
- 관련 윤리 축
- 상황 설명
- 선택지 2개
- 선택 결과
- NPC 반응
- 세계 지표 변화

### 4. 세계 변화

플레이어 선택과 대칭자 흔적은 세계 지표를 바꾼다.

| 지표 key | 이름 | 의미 |
| --- | --- | --- |
| `warmth` | 온기 | 서로를 돌보는 힘 |
| `order` | 균형 | 규칙과 안정 |
| `breath` | 숨결 | 자유, 회복, 생명력 |
| `tension` | 균열 | 갈등, 불신, 압력 |

### 5. 대칭자 흔적

플레이어가 한 장소에서 선택하면 대칭자는 다른 장소에 반대 성향의 흔적을 남긴다.

MVP에서는 가장 단순한 규칙을 사용한다.

- 현재 해결한 딜레마의 다음 딜레마 장소에 대칭자 흔적을 남긴다.
- 마지막 딜레마를 해결하면 첫 장소 또는 엔딩용 흔적으로 순환해도 된다.
- 대칭자 선택은 해당 딜레마 축에서 대칭자의 성향과 맞는 선택지다.

향후에는 위치, NPC, 과거 선택, 세계 상태를 고려해 더 정교하게 바꿀 수 있다.

### 6. 통합/회고 엔딩

모든 딜레마를 해결하면 엔딩 오버레이를 연다.

플레이어는 대칭자의 흔적 중 하나를 선택한다.

선택 결과:

- 그 흔적을 지우지 않는다.
- 플레이어 정체성이 반대의 진실을 품는다는 텍스트가 나온다.
- 세계 지표에 따라 세계 판정 문장이 달라진다.

엔딩은 승패가 아니다. 엔딩은 "내가 선택하지 않은 가치까지 견딜 수 있는가"를 묻는 회고다.

## 7. MVP 콘텐츠 명세

MVP에는 딜레마 5개를 포함한다. 기존 3개는 유지하고, 새 딜레마 2개를 추가한다.

### 딜레마 목록

| id | 장소명 | 축 | 관련 NPC | 상태 |
| --- | --- | --- | --- | --- |
| `village` | 물 부족 마을 | `care` | 아이 / 장로 | 기존 |
| `gate` | 폐쇄된 관문 | `agency` | 문지기 / 상인 | 기존 |
| `forest` | 병든 숲 | `bond` | 약초사 / 치료단장 | 기존 |
| `archive` | 불타는 기록관 | `bond` | 기록관장 | 신규 |
| `harbor` | 떠나는 항구 | `agency` | 선장 / 피난민 | 신규 |

### 신규 딜레마 1: 불타는 기록관

권장 데이터:

- `id`: `archive`
- `name`: `불타는 기록관`
- `axis`: `bond`
- `color`: `#6f7fb8`
- `location`: 기존 맵 안에서 빈 공간에 배치한다.
- `prompt`: 기록관에 불이 번지고 있다. 안에는 전염병 치료 기록과 전쟁을 부른 금지 주문 기록이 함께 남아 있다.
- `unresolved`: 연기가 지붕 틈으로 새고 있다. 사람들은 지식을 구할지 봉인할지 결정을 기다린다.

선택지 A:

- `id`: `open-archive`
- `pole`: `left`
- `title`: `공개된 기록`
- `tag`: `신뢰`
- `body`: 치료 기록과 금지 주문 기록을 모두 공개하고, 공동 검토를 맡긴다.
- `outcome`: 치료법은 살아남았지만 위험한 주문도 사람들 손에 들어갔다. 기록관 앞에는 감사와 두려움이 함께 모였다.
- `npc`: 기록관장이 탄 장갑을 내려다본다. "숨긴 지식은 안전했지만, 죽어가던 사람들에게는 닿지 않았지."
- `worldDelta`: `{ warmth: 1, order: -1, breath: 3, tension: 1 }`

선택지 B:

- `id`: `sealed-archive`
- `pole`: `right`
- `title`: `봉인된 서고`
- `tag`: `통제`
- `body`: 치료 기록만 선별하고, 금지 주문 기록은 봉인한다.
- `outcome`: 위험한 지식은 막혔다. 그러나 어떤 치료법이 사라졌는지는 아무도 확인할 수 없게 됐다.
- `npc`: 기록관장이 열쇠를 쥔다. "살릴 지식과 죽일 지식을 내가 구분했다. 그 책임도 내게 남겠지."
- `worldDelta`: `{ warmth: -1, order: 3, breath: -1, tension: 1 }`

### 신규 딜레마 2: 떠나는 항구

권장 데이터:

- `id`: `harbor`
- `name`: `떠나는 항구`
- `axis`: `agency`
- `color`: `#4f9aa0`
- `location`: 기존 맵 안에서 빈 공간에 배치한다.
- `prompt`: 폭풍 전 마지막 배가 항구에 묶여 있다. 피난민들은 지금 떠나자고 하고, 선장은 질서 없는 출항이 모두를 죽일 수 있다고 말한다.
- `unresolved`: 밧줄이 젖은 나무 말뚝을 긁는다. 항구는 떠남과 기다림 사이에서 흔들린다.

선택지 A:

- `id`: `free-sailing`
- `pole`: `left`
- `title`: `열린 출항`
- `tag`: `자유`
- `body`: 배를 열고 원하는 사람부터 떠나게 한다. 위험은 각자가 감당한다.
- `outcome`: 일부는 바다로 나갔고 일부는 남겨졌다. 항구에는 빈 짐과 살아난 이름이 함께 남았다.
- `npc`: 선장이 젖은 밧줄을 놓는다. "명령은 없었지만, 누군가는 오늘 자기 삶을 되찾았군."
- `worldDelta`: `{ warmth: 1, order: -2, breath: 3, tension: 1 }`

선택지 B:

- `id`: `ordered-boarding`
- `pole`: `right`
- `title`: `명부의 승선`
- `tag`: `질서`
- `body`: 명부를 만들고 어린이, 환자, 항해 인력을 우선 태운다.
- `outcome`: 배는 안전하게 떠났다. 하지만 명부 밖의 사람들은 자신이 버려졌다는 사실을 정확히 알게 됐다.
- `npc`: 피난민이 젖은 종이를 움켜쥔다. "질서가 있어서 살았겠지. 질서 때문에 남았고."
- `worldDelta`: `{ warmth: -1, order: 3, breath: 0, tension: 2 }`

## 8. 데이터 구조 명세

### `Axis`

현재 구조를 유지한다.

필수 필드:

- `key`
- `name`
- `left.label`
- `left.title`
- `left.copy`
- `right.label`
- `right.title`
- `right.copy`

### `Dilemma`

필수 필드:

- `id`: stable id
- `name`: 화면에 표시할 장소명
- `axis`: `care`, `agency`, `bond` 중 하나
- `color`: 지도 노드 색상
- `location`: `{ x, y }`
- `prompt`: 선택 전 상황 설명
- `unresolved`: 미해결 상태의 장소 설명
- `options`: 선택지 배열

### `DilemmaOption`

필수 필드:

- `id`
- `pole`: `left` 또는 `right`
- `title`
- `tag`
- `body`
- `outcome`
- `npc`
- `worldDelta`

### `WorldDelta`

필수 필드:

- `warmth`
- `order`
- `breath`
- `tension`

누락된 값은 0으로 처리한다.

### `RivalMove`

필수 필드:

- `milestone`
- `sourceDilemmaId`
- `targetDilemmaId`
- `choiceId`
- `title`
- `tag`
- `summary`
- `worldDelta`

권장 추가 필드:

- `evidenceText`
- `relatedNpcIds`
- `canBeIntegrated`

MVP에서는 기존 필드만으로 구현해도 된다. 단, 새 필드를 추가한다면 테스트도 함께 추가한다.

### `SavedGame`

저장/재개를 위한 직렬화 데이터다.

필수 필드:

- `version`
- `phase`
- `playerSelections`
- `playerPosition`
- `regions`
- `worldMetrics`
- `rivalMoves`
- `completedCount`
- `savedAt`

저장 위치:

- 브라우저 `localStorage`
- key: `rival-everything:mvp-save`

주의:

- class instance를 그대로 저장하지 않는다.
- 저장 시 plain object로 만들고, 로드 시 `createInitialState` 이후 상태를 복원한다.

## 9. 화면 흐름 명세

### 화면 1: 정체성 선택

사용자 목표:

- 3개 축을 읽고 자신의 성향을 선택한다.
- 선택에 따라 플레이어와 대칭자 프로필 미리보기를 본다.

필수 UI:

- 축 카드 3개
- 각 축의 좌/우 선택 버튼
- 플레이어 칭호
- 대칭자 칭호
- 게임 시작 버튼
- 저장된 게임이 있으면 이어하기 버튼

완료 기준:

- 모든 축에 기본값이 있다.
- 선택 변경 시 프로필 미리보기가 즉시 갱신된다.
- 시작 버튼으로 게임 화면에 진입한다.

### 화면 2: 지도/탐험

사용자 목표:

- 장소를 찾고 이동한다.
- 해결 가능한 딜레마를 확인한다.
- 세계 상태와 대칭자 흔적을 본다.

필수 UI:

- 캔버스 지도
- 현재 가까운 장소 안내
- 상호작용 버튼
- 세계 지표
- 지역 상태 패널
- 대칭자 로그
- 새 게임 버튼

완료 기준:

- 5개 장소가 모두 지도에 표시된다.
- 해결된 장소와 미해결 장소가 구분된다.
- 대칭자 흔적이 있는 장소가 시각적으로 구분된다.

### 화면 3: 딜레마 선택

사용자 목표:

- 상황을 읽고 선택한다.
- 선택이 자신의 축인지 대칭자의 축인지 이해한다.

필수 UI:

- 장소명
- 딜레마 제목
- 상황 설명
- 선택지 2개
- 각 선택지의 태그
- 닫기 버튼

완료 기준:

- 선택 결과와 NPC 반응이 지역 패널에 반영된다.
- 대칭자 흔적이 생성된다.

### 화면 4: 대칭자 흔적

사용자 목표:

- 대칭자가 어디서 어떤 반대 선택을 했는지 이해한다.

필수 UI:

- 대칭자 로그
- 지도 위 흔적 표시
- 지역 패널의 흔적 요약

완료 기준:

- 플레이어 선택 직후 대칭자 로그가 1개 증가한다.
- 대칭자 흔적의 target 장소가 지도와 패널에서 확인된다.

### 화면 5: 통합/회고 엔딩

사용자 목표:

- 대칭자의 흔적 중 하나를 선택하고 엔딩 텍스트를 본다.

필수 UI:

- 대칭자 흔적 선택 카드
- 최종 엔딩 텍스트
- 다시 시작 버튼

완료 기준:

- 모든 딜레마 해결 후 자동 또는 버튼으로 엔딩에 진입한다.
- 선택한 대칭자 흔적의 tag가 엔딩 텍스트에 반영된다.
- 다시 시작 시 저장 상태가 초기화된다.

## 14. 테스트 명세

`tests/core.test.js`는 최소 다음을 검증해야 한다.

### 데이터 검증

- `DILEMMAS.length === 5`
- 모든 `Dilemma.id`가 고유하다.
- 모든 딜레마에 `location.x`, `location.y`가 있다.
- 모든 딜레마에 `options.length === 2`
- 모든 딜레마에 `left`, `right` 선택지가 있다.
- 모든 선택지에 `worldDelta`가 있다.

### 정체성 검증

- 플레이어 선택이 올바르게 저장된다.
- 대칭자 선택이 반전된다.
- `getLabel`이 올바른 label을 반환한다.

### 진행 검증

- 딜레마 하나를 해결하면 해당 지역이 resolved 된다.
- 같은 딜레마를 다시 해결하려 하면 무시된다.
- 딜레마 해결 시 대칭자 흔적이 하나 생성된다.
- 5개 딜레마 해결 후 `completedCount === 5`
- 5개 딜레마 해결 후 `phase === "integration"`

### 엔딩 검증

- `buildEndingText` 결과에 `대칭자`가 포함된다.
- 통합한 흔적의 `tag`가 엔딩에 반영된다.
- 세계 판정 문장이 포함된다.

### 저장 검증

저장/로드 헬퍼를 구현했다면 다음을 추가한다.

- serialize 결과가 JSON stringify 가능하다.
- restore 후 `completedCount`가 유지된다.
- restore 후 `world.metrics`가 유지된다.
- restore 후 `rivalMoves`가 유지된다.

## 16. 콘텐츠 작성 규칙
